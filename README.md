# Онлайн-сервис живодноводческой фермы (backend)

Документация api /swagger-ui/index.html

## Руководство по стилю кода
- Классы в `PascalCase`;
- Переменные в `camelCase`;
- Константы в `SCREAMING_SNAKE_CASE`;
- Табы - 4 пробела;
- Максимальная длинна строки - стандартная для ide (120 символов);
- Комментарии и java-доки указываем на русском языке;
- Вместо `@Autowired` используем `@RequiredArgsConstructor`;
- Интерфейсы сервисов должны быть покрыты java-доками;
- Используем, по возможности, `@Builder`;
- Не забывать про автоматическое форматирование кода при помощи встроенного инструмента в Intellij Idea `Ctrl + Alt + L`;
- Оптимизация неиспользуемых импортов `Ctrl + Alt + O`;
- Не превращать код в "лапшу";
- В миграциях - все SQL операторы прописываются в нижнем регистре;
- При объявлении переменных (в том числе локальных), если логикой не подразумевается изменение ссылки этой переменной,
  она должна быть задекларирована модификатором final;
- **ЗАПРЕЩЕНО** использовать какие-либо самописные библиотеки универсальных фильтров;
- **ЗАПРЕЩЕНО** создавать вьюхи в базе данных;

## Сборка и библиотеки
- Java 17;
- Сборщик - maven. Используется враппер (версия с исходниками);
- Spring boot 3.5.6;
- Liquibase - библиотека миграции структуры БД;
- Testcontainers - библиотека для использования реальных зависимостей в docker контейнерах;

## Миграция БД
- Фреймворк миграции "Liquibase";
- Директория расположения скриптов: resources/db/migration;
- Конфигурация подключения скриптов миграции: resources/db/changelog.xml
- Формат скриптов миграции SQL changeset (https://docs.liquibase.com/concepts/changelogs/sql-format.html);
- Формат наименования файлов миграции `V{YYYYMMDD}_{hhmm}__{смысловое наименование}.sql` Прим.: V20250805_1015__enum.sql
- Все SQL операторы прописываются в нижнем регистре;
- При создании таблиц/добавлении полей - всегда прописывать sql комментарии;
- Первичные ключи - uuid. При добавлении миграций с наполнениями, заполнять первичные ключи сгенерированными значениями.
  Можно воспользоваться любыми онлайн генераторами.

## Структура пакетов

- ru.farming.livestock_farm - корневой пакет;
- ru.farming.livestock_farm.config - конфигурация сервиса;
- ru.farming.livestock_farm.dao - сущности и репозитории;
- ru.farming.livestock_farm.api - интерфейсы rest api c open api документацией;
- ru.farming.livestock_farm.controller - реализация rest api;
- ru.farming.livestock_farm.command - слой с исполняемыми командами;
- ru.farming.livestock_farm.core - ядровой слой, содержащий абстракции;

## Контроль версий
- Ветка разработки - `develop`;
- Релизная ветка - `master`;
- Формат рабочей фичи: `feature/{номер задачи}` Прим.: feature/LFARM-0001;
- Формат заголовка коммита: `[LFARM-0001] описание коммита` Прим.: [LFARM-0001] добавление сущности КРС;
- Перед заливкой фичи в origin, делаем rebase относительно develop ветки. При возникновении конфликтов - исправляем во время процесса ребейза;
- При создании PR - всегда проставляем признак удаления фичи после слияния.
